부하를 나누는 방식의 차이

      Kafka를 선택한 이유

      정시 배치에 임박·만료 알림이 한꺼번에 몰리는 상황을 고려했어요. 이 부하를 여러 브로커와 소비자에게 나누는 방식이 두 기술에서 달라요.

      1. RabbitMQ 일반 큐브로커를 추가해도 기존 큐 하나가 자동으로 나뉘지 않아요. 부하를 나누려면 여러 큐와 메시지 분배 규칙을 직접 구성해야 해요.
      2. Kafka 파티션토픽을 여러 파티션으로 나누고, 같은 소비자 그룹의 소비자들이 파티션을 나눠 맡는 구조를 제공해요. 이 구조를 몰리는 배치 작업의 분산에 활용하려고 해요.
      3. 복제와 분할은 구분해요두 기술 모두 복제와 확장을 지원해요. 복제는 장애 대비이고, 분할은 처리 부하를 나누는 일이에요.
      4. Kafka도 관리가 필요해요같은 냉장고 키에 작업이 몰리면 특정 파티션에 집중될 수 있어요. 브로커를 추가한 뒤에는 파티션 재배치도 필요해요.
