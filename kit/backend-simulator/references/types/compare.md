# ④ 개선 비교

지금 구조와 바꾼 구조를 같은 상황에서 비교한다. 지금 구조 쪽은 실측에 맞춘다.

예시: 푸시 발송 구조 비교 #192(`templates/index-time.html`의 예시 CONFIG). 상황 4개: 발송 중 서버 재시작, 서버 2대, 메모리에 올리는 양, 재시도 지연.

## 언제

- "바꾸면 얼마나 나아져", "왜 이 구조로 바꿨어"를 실측과 함께 보여 줄 때

## 근거

- 지금 구조: 저장소·브랜치·날짜·커밋과 코드 사실
- 바꾼 구조: 구현됐으면 코드, 구현 전이면 설계 문서. 구현 전 수치는 "구현 전 모델 예상"
- 실측: 이슈 번호, 조건(데이터 양, 격리 환경, 외부 응답 스텁, 동시 수), 결과

## 화면

- **패널 2개**: 왼쪽 **현재 구조**(주황), 오른쪽 **바꾼 구조**(파랑, 이름은 구조 이름으로. 예: "DB 워커 구조").
- **탭 = 상황**. 상황마다 성격을 정한다: 실패 제거 / 규모 대응 / 우선순위 트레이드오프.
- 처리량은 실측 처리 시간에 맞춘다. 같은 상황 안에서 두 패널의 칸 수와 처리 속도는 같게 둔다. 차이는 구조에서만 나오게 한다.
- 시간 축: 초, 1분 간격. 시간표 줄: 상황에 맞게(발송 / 재시도 등).

## 설명 카드

- 머리띠: 왼쪽 **현재 구조** / 오른쪽 바꾼 구조 이름.
- 비교가 현재/바꾼 짝이 아니면 상황에 맞게 쓴다. 예: "채택 안 함" / "채택".
- 트레이드오프 상황은 ③ 끝 단계 풀이에 무엇을 내주는지 쓴다. 예: "대신 그만큼 첫 발송이 조금 밀려요".

## README에 더 적을 것

- 상황 표: 상황 | 현재 구조 | 바꾼 구조 | 성격
- 실측표와 실험 조건, 측정 범위 밖 항목
- 바꾼 구조 수치가 구현 전 모델 예상인지 여부

## 추가 검사

- 두 패널의 시작 시점과 축이 같은지
- 지금 구조 쪽 결과가 실측과 맞는지(예: 32,000건 → 453.788초, 재시도 지연 153.218초). 모델 값과 실측 값을 README에 나란히 적는다.
