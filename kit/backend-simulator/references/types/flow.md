# ② 흐름 추적

한 기능의 요청과 데이터가 어떤 메서드, 테이블, 메시지를 지나는지 보여 준다. 두 구조를 비교하지 않는다.

예시: 다먹자 비동기 구조(2026-11-10, KTB4-5th-BE origin/dev 4b13f19a). 기능 5개(이미지 분석, 요리 추천, 구성원 변경, 임박·만료, 요리 적용).

## 언제

- "이 기능은 어디를 거쳐", "요청 안에서 끝나는 일과 나중에 하는 일이 뭐야"

## 근거

- 호출 경로(컨트롤러 → 서비스 → 저장소), 트랜잭션 경계, 발행·구독 지점, 쿼리, 토픽 이름
- 설정으로 켜고 끄는 경로가 있으면 설정 키와 기본값(`application.yml:줄`)

## 화면

- **패널 1개**. **탭 = 기능**. 상자 위치는 모든 탭에서 같고, 점이 가는 길만 다르다. 쓰지 않는 상자와 선은 흐리게 둔다(`dim: true`).
- 점 색:
  - 주황(`cur`): 요청 안에서 저장한 기록
  - 파랑(`wrk`): 워커가 옮기는 메시지
  - 초록(`ok`): 사용자에게 알리는 신호
- 설정으로 켜고 끄는 경로가 있으면 "○○ 경로 꺼짐(기본값) / 켜짐"을 상황 두 개로 나눈다. 두 상황은 같은 축을 쓴다.
- 시간 축: 실측이 없으면 순서만 쓰고 초 단위 숫자를 쓰지 않는다. 실측이 있으면 초.
- 시간표 줄: 요청 / 발행 / 처리 / 화면 / 푸시.

## 설명 카드

- 머리띠: 왼쪽 **요청 안에서 끝나는 일** / 오른쪽 **워커가 나중에 하는 일**.
- 풀이 줄에 트랜잭션, 커밋 후 발행, 아웃박스, 소비자 그룹, 오프셋 같은 용어를 짧게 푼다.
- 코드 상자: `@Transactional` 메서드, 발행 줄, 리스너 메서드, 설정 기본값.

## README에 더 적을 것

- 설정 스위치: 키 | 기본값 | 근거 `application.yml:줄`
- 기능별 경로: 기능 | 요청 안 | 나중에

## 추가 검사

- 같은 상황 안의 켬/끔이 같은 축을 쓰는지(명세 확인)
- 흐린 상자로 점이 지나가지 않는지(스크린샷)
