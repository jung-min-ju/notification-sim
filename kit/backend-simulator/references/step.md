# 단계형 뼈대 (`templates/index-step.html`)

구성요소가 많고, 메시지 하나가 어떤 순서로 무엇을 바꾸는지 보여 줄 때 쓴다. ① 구조 지도와 ② 흐름 추적의 기본 뼈대다(2026-11-19).
본보기는 notification-v2 화면이다(https://jung-min-ju.github.io/notification-sim/notification-v2/#s6).

시간형(`index-time.html`)과 다른 점:

| | 시간형 | 단계형 |
|---|---|---|
| 진행 | 모델 시간이 흐름, 시간표 있음 | 단계 1/N, 이전·다음, 시간표 없음 |
| 움직이는 것 | 작업 N건을 뜻하는 점 여러 개 | 이름 붙은 메시지 하나씩 |
| 상자 안 | 상자 아래 숫자 하나 | 테이블·큐의 값 줄이 바뀜(없음 → 대기 → 수락) |
| 설명 | 아래 카드 두 개(30%), 단계 ①②③ | 왼쪽 칸: 지금 단계, 지금 하는 일, 단계 목록 |
| 잘 보이는 것 | 양이 쌓이고 막히는 것 | 많은 구성요소 사이의 순서와 상태 |

공통 규칙(`common.md`)의 목표, 움직임, 글, 색·글꼴, 삽입 모드, 검사는 그대로 따른다. 이 파일은 화면 구성과 CONFIG만 다룬다.

## 화면 구성

위에서부터: (있으면) 화면 이야기 줄 → 재생 줄(상황 고르기, 재생, 이전, 다음, 처음으로, 속도, `2 / 8`) → **16:10 한 화면**.

16:10 한 화면은 **왼쪽 30 : 오른쪽 70**이다. 오른쪽은 그림과 범례 한 줄뿐이다(코드 상자 없음, 2026-11-19). 노트북 화면 전용이며 그림 폭 700px 아래로 줄이지 않는다. 삽입 모드 최대 폭은 블로그 본문 폭인 720px이다.

### 왼쪽 칸

- 맨 위: 단계 묶음 이름(흐름 / 문제 / 정리)과 지금 단계 제목(28자 이하, 해요체)
- **지금 하는 일**: 글머리 2~4개, 하나에 36자 이하. 무엇이 움직이는지와 왜 그런지를 쓴다.
  - 용어 풀이는 그 용어가 처음 나오는 단계의 글머리에 "선점: 다른 워커가 같은 작업을 못 잡게 하는 표시"처럼 짧게 넣는다. 용어 목록을 따로 두지 않는다.
- 단계 목록: 3~8개. 흐름 / 문제 / 정리로 묶는다. 누르면 그 단계로 가서 재생한다(Enter·Space 포함).
- 왼쪽 칸 안에 넘치지 않아야 한다. 넘치면 글을 줄이거나 단계를 나눈다.

### 오른쪽: 그림 (논리 크기는 `view`, 기본 800 × 660)

- 오른쪽 칸은 세로로 길다(약 1.2 : 1). 구성요소를 세로로 넉넉히 펼쳐 칸을 채운다. 가로로 납작하게 두면 아래가 빈다.

- 구성요소 종류:
  - `box`: 서버, 워커
  - `db`: 테이블. 원통 모양이고 안에 값 줄이 있다.
  - `client`: 사용자 기기
  - `ext`: 외부 서비스
  - `candidate: true`: 해결 후보로 추가되는 장치. 점선 테두리로 그린다.
- 지금 단계에 쓰는 구성요소(`active`)는 파란 테두리로 강조하고, 나머지는 흐리게 둔다.
- 선 색은 메시지 종류를 따른다:
  - `req` 요청·저장: 파랑
  - `res` 응답·조회 결과: 초록
  - `sig` 신호·외부 호출: 주황
  - `fail` 실패: 빨강
- 메시지는 단계 안에서 차례로 하나씩 움직인다. 이름표가 점 위에 붙어 간다. 실패 메시지는 가운데에서 ✕가 생긴다.
- 메시지가 도착하면 값 줄이 바뀐다(`set`). 색으로 상태를 나타낸다: 대기 `pend`(노랑), 완료 `ok`(초록), 실패 `bad`(빨강).
- 메모(`notes`)는 그 단계의 메시지가 다 도착한 뒤 구성요소 아래쪽에 보인다. 덮개(`covers`)는 단계 시작부터 보인다. 예: "응답 기다리는 중".
- 선은 직접 경로를 잡는다. 선끼리 교차하지 않고, 양끝이 아닌 구성요소를 지나가지 않게 한다. 이름표가 양끝이 아닌 구성요소에 걸치지 않도록 구성요소 사이 간격을 둔다(이름표 폭의 절반 이상).

### 오른쪽 맨 아래

- 범례 한 줄: 선 색 네 가지(+ 후보 장치가 있으면 점선)
- 코드는 화면에 두지 않는다. 단계마다 근거 `파일:줄`을 `src`에 적고 README로 옮긴다. 정리 단계의 근거는 설정값(`application.yml:줄`)이나 핵심 메서드다.

## 재생

- 메시지 하나 1.15초(보통 속도), 단계 끝에서 1.8초 멈춘 뒤 다음 단계로 넘어간다. 마지막 단계에서 멈춘다.
- 이전·다음·처음으로는 재생을 멈추고 그 단계의 처음으로 간다. 단계 목록을 누르면 그 단계부터 재생한다.
- 삽입 모드: `?embed&s=<상황>`. 화면에 보일 때만 재생하고, 처음 보일 때 1단계부터 시작한다.

## CONFIG 형식

```js
const CONFIG = {
  title: '화면 제목',
  kind: 'flow',                       // map | flow
  view: [800, 660],
  chapters: null,                     // 화면 이야기 줄: [{label: '① 정상 흐름', href: '../a/', current: true}, ...]
  nodes: [
    {id: 'S1', type: 'box', x, y, w, h, title: '서버 S1', sub: '08시 배치 실행'},
    {id: 'J', type: 'db', x, y, w, h, title: '발송 작업 테이블',
     rows: [{key: 'job', label: '냉장고1 · U1 노트북', value: '없음'}]},
    {id: 'Q', type: 'box', ..., candidate: true}],
  texts: [{x, y, text: '두 테이블은 같은 DB 안에 있어요', align: 'middle'}],
  edges: [{id: 'S1-J', from: 'S1', to: 'J', pts: [[290, 70], [380, 70]]}],
  legend: [['req', '요청·저장'], ['res', '응답·조회 결과'], ['sig', '신호·외부 호출'], ['fail', '실패']],
  scenes: [{
    id: 'flow', tab: '전체 흐름', init: {job: ['대기', 'pend']},   // init: 이 상황의 처음 값(없으면 rows의 value)
    steps: [{
      group: 'flow',                  // flow | prob | sum → 흐름 / 문제 / 정리
      title: '알림과 대기 작업을 함께 저장해요',
      active: ['S1', 'ND', 'J'],
      doing: ['…', '…'],
      msgs: [{edge: 'S1-J', label: '대기 작업', kind: 'req', set: {job: ['대기', 'pend']}},
             {edge: 'W1-J', rev: true, label: '응답', kind: 'res'},      // rev: 선을 거꾸로
             {edge: 'W1-J', label: '결과 저장', kind: 'fail', fail: true}],
      notes: {S1: ['함께 커밋', 'ok']},
      covers: {W1: '응답 기다리는 중'},
      src: 'ExpirationNotificationService.java:55'   // 근거. 화면에 안 나오고 README로 옮긴다
    }]
  }]
};
```

테스트 훅 `window.__sim`: `type: 'step'`, `scenes`, `scene(id)`, `steps`, `step`, `playing`, `at(k, u)`(k단계, 메시지 진행 u = 0~1, 생략하면 끝 상태), `msgTimes(k)`, `config`.

## 검사 (`check.js`가 단계형을 알아보고 따로 돈다)

- 단계 내용: 단계 3~8개, 묶음 값, 지금 하는 일 2~4개(36자 이하), 제목 28자 이하, `active`·`notes`·`covers`의 구성요소와 `msgs`의 선·값 줄이 실제로 있는지, 단계마다 근거(`src`)가 있는지
- 그림 배치: 구성요소끼리 너무 가까운지, 그림 밖으로 나갔는지, 선이 양끝이 아닌 구성요소를 지나는지, 선끼리 교차하는지, 구성요소 안 글자가 칸을 넘는지, 값 줄의 이름과 값이 겹치는지
- 메시지 이름표: 메시지마다 세 지점에서 양끝이 아닌 구성요소에 걸치는지, 그림 밖으로 나가는지
- 이동: 다음, 이전, 단계 클릭(재생 시작), Enter
- 폭(삽입 720, 일반 740·900·1280)마다 가로 스크롤, 16:10, 왼쪽 칸 넘침
- iframe 높이(삽입 720), 스크린샷(상황 × 단계 끝, 이동 중, 삽입 720, 다크)
